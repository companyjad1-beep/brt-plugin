# report — 성과 분석 → 다음 생산 가중치

report 모드에서 로드한다. `ledger.md`의 지표를 분석해 골격·채널의 승격/도태를 판정하고, 다음 write에 적용할 형식 권고를 남긴다.

## 판정 규칙

- **비교는 같은 채널 안에서만.** 채널마다 지표 단위가 다르다(collect.md 채널별 절차 표). 쓰레드 좋아요와 블로그 조회수를 한 줄에 세우지 않는다.
- **표본 경고를 먼저 단다.** 게시물 3편 이하이거나 게시 후 3일 미만인 행이 섞여 있으면 "판정이 아니라 참고"라고 명시한다. 얇은 표본으로 골격을 도태시키지 않는다.
- **목적 대비로 읽는다.** ledger의 목적 칸 기준으로 본다 — 팔로워 목적 글은 팔로워·도달로, 검색유입 목적 글은 조회수·유입 검색어로, 전환 목적 글은 프로필 방문·설치 경로로. 목적과 다른 지표가 좋은 건 성공이 아니라 목적 미달이다.

## 골격 승격/도태 (skeletons.md 갱신)

| 판정 | 조건 | 처리 |
|---|---|---|
| 승격 | 같은 채널 내 우리 글 중앙값 대비 상위 성과 2회 이상 | 상태를 `승격`으로 — 다음 batch에서 골격을 우선 재사용한다. 골격 우선 재사용은 주제·사실 재사용 허가가 아니다. |
| 도태 | 같은 골격 2회 이상 사용, 매번 중앙값 미달 | 상태를 `도태(사유·날짜)`로 — 재사용 금지, 기록은 남긴다 |
| 유지 | 그 외 | `활성` 유지 |

## 출력

`ledger.md` 하단에 `## 리포트 <날짜>` 섹션을 추가한다:

1. **채널별 요약** — 편수·지표 중앙값·최고/최저 편(id).
2. **먹힌 것** — 상위 편의 공통점(주제 성격·골격ID·훅 유형). 1편뿐이면 공통점이라 부르지 않는다.
3. **안 먹힌 것** — 하위 편의 공통점과 추정 원인. 추정은 추정이라고 쓴다.
4. **다음 write 권고** — 성과가 좋았던 훅 구조·형태·길이·전개·종결·CTA·골격을 기록한다. 주제 방향은 다음 write의 검색 토큰으로만 2~3개 제안한다. 특정 과거 주제·제품·사례를 자동 재생산하라고 지시하지 않는다. batch 권고는 기존 승인형 계획에만 적용한다.
5. **재활용(땔감) 후보** — 게시 3~6개월 경과 그리고 같은 채널 중앙값 상위인 글을 고른다. 쓰레드 행에만 threads-ops.md §3 변주(첫 줄·종결 리라이팅 / 요약·질문형·반론형)를 권고하고, 비쓰레드 채널은 해당 채널의 현재 레퍼런스·형태 규칙과 같은 채널 지표를 적용하며 threads-ops.md §3·§5를 적용하지 않는다. 후보가 없으면 "없음"이라고 쓴다. 땔감 추천은 신규 write 후보가 아니다. report가 후보를 지목하고 사용자가 해당 글 재활용을 명시했을 때만 recycle로 실행한다. 3~6개월·핵심 메시지 유지·첫 줄/종결/형태 변주를 따르며 가격·정책·시세 등 변동 사실은 재검증한다.
6. **채널별 가설 검증** — 쓰레드 행에 저장·공유 지표가 쌓였을 때만 "저장률 상위 = 도달 상위" 가설(threads-ops.md §5)과 프로필 방문→팔로우 전환율(§4)을 대조한다. 비쓰레드 채널은 collect.md의 해당 채널 지표와 현재 채널 레퍼런스로 가설을 검증하고 threads-ops.md §3·§5를 적용하지 않는다. 재현/반증 이력은 이 ledger 리포트 또는 `docs/marketing/validation.md`에 남기며 `skills/marketing-auto/threads-ops.md`는 절대 수정하지 않는다.

권고까지 쓰고 나면 사용자에게 요약을 보고하고, 다음 생산/다음 write 실행을 제안한다. 사용자가 명시적으로 batch를 요청한 경우에만 다음 batch 실행을 제안한다.
