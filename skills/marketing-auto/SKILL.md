# marketing-auto — 마케팅 자동화 하네스

앱/서비스 프로젝트 루트에서 실행한다. 상태는 전부 대상 프로젝트의 `docs/marketing/`에 남는다.

**북극성**: 콘텐츠 한 편의 최종 판정 기준은 하나 — **"이 글을 본 독자가, 우리가 정한 그 행동을 할 이유가 글 안에 있는가."** 이유가 없으면 아무리 잘 쓴 글도 기각이다. 이 스킬의 전신(marketing-plan)은 목적 없는 글·회사 소개글을 만들어서 폐기됐다. 같은 실패를 구조로 막는다:

1. **목적 게이트** — 모든 콘텐츠는 생산 **전에** 목적과 CTA를 선언하고, 완성 **후에** 그 기준으로 채점된다.
2. **주제 삼각측량** — 한 소스만 믿으면 빗나간다. 세 소스의 교집합만 주제가 된다. [research.md](research.md)
3. **성과 순환** — 게시 결과를 수집·분석해 골격과 주제를 승격/도태시킨다. 돌수록 우리 채널에서 먹히는 것만 남는다.

## 모드

| 모드 | 하는 일 | 문서 |
|---|---|---|
| **batch** (기본) | 주제 선정 → 배치표 승인 → 채널별 생산 → 목적 게이트 → 장부 기록 | 이 문서 + [research.md](research.md) |
| **collect** | 브라우저로 4채널 통계 순회, 게시물별 지표를 장부에 기록 | [collect.md](collect.md) |
| **report** | 장부 분석 → 뭐가 먹혔나 → 골격 승격/도태 + 다음 배치 권고 | [report.md](report.md) |
| **publish** | **미구현 예약석.** 요청받으면 "아직 없음, 게시는 수동"이라고 답한다 | — |

## 상태 파일 (대상 프로젝트)

```
docs/marketing/
  playbook.md      # 프로젝트 마케팅 설정 — 첫 실행 때 생성, 이후 재사용
  ledger.md        # 게시물 대장 — 한 편 = 한 행, 지표는 수집일별 누적
  skeletons.md     # 골격 라이브러리 — 채널별 해부 골격 + 사용 이력 + 성과 태그
  batches/<YYYY-MM-DD>/   # 산출물 (글·캡션·이미지 프롬프트·쇼츠 스크립트)
```

## playbook.md — 첫 실행 게이트

`docs/marketing/playbook.md`가 있으면 읽고 넘어간다. 없으면 여기서 만든다:

1. **자동 추론** — `docs/PRD.md`·`docs/BRAND.md`·`docs/MARKETING.md`(구버전 산출물이 있으면 재료로만)·README·코드베이스를 읽고 아래 표의 초안을 채운다.
2. **미니 인터뷰(3~5문)** — 추론으로 못 채우거나 판단이 필요한 칸만 묻는다. 한 번에 질문 하나 + 추천안. 다 채워져 있으면 "이렇게 추론했다" 확인 한 번만.

| 항목 | 내용 |
|---|---|
| 제품 한 줄 | 무엇을 누구에게 |
| 목적 우선순위 | 검색유입 / 팔로워 / 전환(설치·가입) 중 이 프로젝트의 순서 |
| 계정 전략 | 기본값: 피드형(쓰레드·인스타·쇼츠)=퍼스널 계정(빌드인퍼블릭 서사), 네이버 블로그=주제별 분리(SEO 주제 일관성). 프로젝트별로 덮어쓰기 가능 |
| 채널 | 운영 채널 + 명시적 제외 채널 |
| 재료 금고 | 오리진(왜 만들었나 — 날짜·사건까지)·현장 디테일·내부 수치·강점 목록(기능명 ❌, "그래서 뭐가 풀리나"로 ⭕) |
| 말투 | BRAND 보이스 있으면 재사용, 없으면 brtwritenotai voice 카드 참조 |

게이트: 재료 금고의 오리진이 "우리가 겪어봐서 안다" 수준으로 구체적이지 않으면, 그 재료를 쓰는 주제는 후보에서 뺀다(지어내지 않는다).

## batch 파이프라인

**0. 시작 전 이 문서와 research.md를 Read로 다시 읽는다. 기억으로 돌리지 않는다.** 그리고 아래 표를 그대로 출력하고 칸을 채우며 진행한다:

| 단계 | 산출물 | 완료 |
|---|---|---|
| 1 playbook 로드/생성 | 설정 확정 | ☐ |
| 2 report 반영 | 이전 성과 가중치 (첫 실행이면 생략) | ☐ |
| 3 주제 삼각측량 | 후보별 근거 3종 표 | ☐ |
| 4 배치표 | 주제×채널×목적×CTA×골격 — **사용자 승인 필수** | ☐ |
| 5 레퍼런스·골격 | 채널별 골격 (라이브러리 재사용 우선) | ☐ |
| 6 생산 | brtwritenotai / brtimg 호출 | ☐ |
| 7 목적 게이트 | 편별 채점, 기각분 재생산·폐기 | ☐ |
| 8 장부 기록 | ledger.md 행 추가 | ☐ |

1. **playbook 로드/생성** — 위 게이트.
2. **report 반영** — `ledger.md`에 성과 데이터가 있으면 report.md 규칙으로 가중치를 뽑아 주제·골격 선정에 반영한다. 없으면 생략.
3. **주제 삼각측량** — [research.md](research.md) §1. 사용자가 주제를 직접 줬으면 리서치를 건너뛰고 **검증만** 한다(수요 근거·재료 근거가 있는지 — 없으면 그대로 말하고 대안 제시).
4. **배치표 승인** — 표로 제시하고 사용자 승인 1회. 승인 없이 생산 금지.

   | 주제 | 채널 | 왜 이 채널 | 목적 | CTA 한 문장 | 골격 |
   |---|---|---|---|---|---|

   - "왜 이 채널"은 research.md §2 매칭 규칙으로 채운다.
   - 같은 주제를 두 채널에 실으면 행을 두 개로 — 복붙 금지, 채널별 골격으로 각각 만든다.
   - 규모 기본값: 채널당 1~2편. 편수 요청에 파이프라인을 양보하지 않는다 — 제대로 된 3편이 대충 만든 10편보다 낫다고 먼저 말한다.
5. **레퍼런스·골격** — `skeletons.md`에 그 채널·도메인의 살아있는 골격(도태 안 된 것)이 있으면 재사용. 없으면 research.md §3(글)/§4(영상)로 새로 해부해서 라이브러리에 추가.
6. **생산** — 문장은 전부 `skills/brtwritenotai` 호출(채널 규약·AI티 게이트 포함, 여기서 재구현 금지). 이미지·영상 프롬프트는 `skills/brtimg` 호출. 쇼츠 1편 = 훅 대사 + 초 단위 장면 스크립트 + 장면별 brtimg 영상 프롬프트.
7. **목적 게이트 (편별 채점)** — 하나라도 실패면 기각. 재생산은 1회, 또 실패면 그 편은 폐기하고 이유를 보고한다:
   - **행동 근거**: 배치표의 CTA를 독자가 할 이유가 글 안에 있는가. 특징 나열은 이유가 아니다.
   - **광고 검사**: 우리 제품/강점 분량 20% 이하 + 강점 문단을 지워도 남은 글이 쓸모 있는가. 무너지면 처음부터 광고였다.
   - **품질**: brtwritenotai 게이트(음화·채점) 통과본인가.
8. **장부 기록** — `ledger.md`에 행 추가. 게시는 사용자가 수동으로 한다. **게시 후 URL을 알려주면 그 행에 기록한다** — URL이 있어야 collect가 지표를 붙일 수 있다.

## ledger.md 형식

```markdown
| id | 날짜 | 채널 | 주제 | 목적 | CTA | 골격ID | 산출물 | 게시URL | 지표 |
|---|---|---|---|---|---|---|---|---|---|
| 2026-07-29-th1 | 2026-07-29 | 쓰레드 | ... | 팔로워 | ... | th-피해-01 | batches/2026-07-29/th1.md | (게시 후) | 07-31: 좋아요 12 · 댓글 3 |
```

지표 칸은 collect가 수집일 스탬프와 함께 누적한다. 빈 칸은 빈 칸으로 둔다 — 추측값 기입 금지.

## 경계

- 게시(업로드)는 안 한다. publish 모드는 예약석.
- 수치·원문·반응수는 전부 출처와 함께만. 지어낸 질문·추측 지표가 문서에 들어가면 이 스킬은 실패다.
- 로그인이 필요한 페이지에서 로그인돼 있지 않으면 시도하지 않고 스킵·보고한다.
