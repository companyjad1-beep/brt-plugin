# 파이프라인 — write Phase 0~4 + voice 모드

## write 모드

### Phase 0 — 주제 발굴 (주제가 없을 때만)

사용자가 주제 없이 오면("아무거나 써줘", "블로그 글 10개") **막 짜서 들이밀지 않는다**. 소크라테스식 질문으로 사용자의 실제 소재에서 주제를 끌어낸다.

- 질문 소재 순서: ① 최근 자주 받는 질문(손님·댓글·지인) ② 최근에 팔린 것·안 팔린 것·실패한 것 ③ 갖고 있는 숫자(매출·시세·원가·측정치) ④ 남들이 틀리게 아는 것(통념 반박거리).
- 한 턴 1~2문. 답이 나오면 그 답에서 **주제 후보 2~3개를 주장 형태로** 도출해 제시하고 고르게 한다 — "아이폰14 시세"(✗ 소재)가 아니라 "아이폰14는 지금 팔 타이밍이다, 9월 신형 발표에 떨어진다"(✓ 주장).
- 내가 접근 가능한 데이터(newz면 시세 DB·AGENTS 운영 실화)가 있으면 묻기 전에 후보를 직접 도출해 먼저 제시한다 — 질문은 데이터로 못 채우는 부분에만.
- 벌크 요청(N개)이면 여기서 슬레이트를 만들되 **실측 소스를 1:1로 배정 못 하는 주제는 탈락**시킨다 — 소스 없는 주제로 쓴 글이 곧 AI 티(경험 없는 일반론).
- 주제가 확정되면 Phase 1로 — 주제 슬롯은 이미 차 있으니 나머지 슬롯만 본다.

### Phase 1 — 소재 인테이크 + 우로보로스 인터뷰 (게이트)

다음 3개 슬롯이 찰 때까지 초안을 시작하지 않는다.

1. **주제 한 문장** — 이 글의 주장 하나. "A부터 Z까지" 류 백과사전형이면 쪼개서 하나만 고르게 한다.
2. **독자 1명 특정** — "여러분"이 아니라 "갤럭시 쓰다가 아이폰 넘어가려는 사람"처럼. 독자를 정하면 어휘가 아니라 **정보 선택**을 그 수준에 맞춘다: 그 독자가 몰라도 되는 전문 디테일은 통째로 버린다(음화 29 — 쉬운 말투에 어려운 내용 전부는 AI 티).
3. **실측 디테일 ≥ 1** — 날짜·실제 수치·구체 모델명·직접 겪은 일. newz 작업이면 시세 DB·검수 데이터·폰가비 매입가·운영 실화(예: "신품가 기준으로 잡았다가 구형폰 4배 과대매입 날 뻔한 일")를 우선 소스로 쓴다. 일반 사용자·소상공인 글이면 본인 사업 숫자(매출·원가·재고·단골 사례)나 날짜 붙은 직접 경험이 같은 역할이다. **일반론만으로는 쓰지 않는다** — 이게 이 스킬과 그냥 "글 써줘"의 차이.

실측 디테일은 현재 주제의 것만 인정한다. 직전 초안·다른 제품·이전 주제의 수치가 컨텍스트에 있어도 슬롯을 채운 것으로 치지 않는다. 주제·제품이 바뀌면 슬롯 3을 비우고 인터뷰 또는 현재 fact pack으로 다시 채운다.

빈 슬롯은 **우로보로스식 인터뷰**로 받는다:

- 한 턴에 질문 1~2개만. 질문 목록 폭탄 금지.
- 빈 슬롯을 정확히 조준한 구체 질문으로 — "실측 데이터 주세요"(✗)가 아니라 "이 글에 넣을 시세, prod 시세 DB에서 내가 뽑을까 아니면 갖고 있는 숫자 있어?"(✓).
- 사용자가 "모르겠다/알아서"라고 하면 선택지 2~3개를 제시하고 고르게 한다. newz면 시세 DB 조회·검수 통계·폰가비 매입/매도가·운영 실화·커뮤니티 반응, 일반 사용자면 본인 매출/원가 숫자·고객 응대 사례·날짜 있는 경험담·직접 찍은 비교 데이터.
- 답변이 새 구멍을 드러내면 후속 질문으로 파고든다. 단 3슬롯 + (권장) 판단 방향("이 글의 결론을 어느 쪽으로 세울까")이 차면 즉시 종료 — 총 5문 이내, 완벽주의로 늘어지지 않는다.
- 내가 직접 채울 수 있는 슬롯은 묻지 말고 채운다(예: 시세는 prod DB 조회, 운영 실화는 AGENTS.md 기록) — 인터뷰는 나한테 없는 것만 받는 장치다.

**집필 중 구멍도 동일 규칙**: Phase 2에서 쓰다가 필요한 수치·사실이 없으면 지어내지 말고 그 지점에 `[확인 필요: ○○]` 마커를 박고 멈춰서 물어본다. 마커가 남은 초안은 게이트를 통과할 수 없다.

### Phase 2 — 초안

`core/rulebook.md`의 양화 22기법을 적용해 작성한다. 특히:
- 첫 문장 = 실측 디테일 (인사·예고 금지)
- 판단을 내린다 (양시론 결론 금지)
- 문장 길이 들쭉날쭉 + 종결어미 변주 (같은 종결 3연속 금지)
- 한 글에 한 주장
- 빈 수사는 삭제가 아니라 치환 — 검증 가능한 구체 팩트 하나로 바꾼다. 넣을 팩트가 없으면 그 문장은 애초에 필요 없다.

말투(존대 단계)·Voice Card·문체 프리셋·채널별 작성 규칙은 `core/channels.md`를 따른다.

### Phase 3 — 자체 탐지·채점 (게이트)

탐지·채점 실행법과 채점기 캐비앗은 `core/eval.md`를 따른다. 게이트 정의:

1. 초안을 스팬 단위로 스캔해 S1/S2 카운트, `_workspace/brtwritenotai/{YYYY-MM-DD-NNN}/draft.md` 저장 후 정량 채점.
2. **게이트**: ① S1 = 0건 ② S2 ≤ 2건 ③ risk_band가 최악 밴드가 아닐 것 ④ 실측 디테일 ≥1 + 명시적 판단 ≥1 잔존 ⑤ `[확인 필요]` 마커 0건.
3. 게이트 실패 → 해당 스팬만 수술적 수정 후 재채점. 최대 2회. 수정은 티 **밀도**를 낮추는 방향으로만 — 걸린 단어를 전부 걷어내는 과교정은 그것대로 기계 티다. 그래도 실패면 잔존 리포트와 함께 산출하고 `--strict` 윤문(humanize-korean) 권고.
4. **숏폼 예외**: thread·instagram·reply 등 300자 미만 산출물은 정량 채점을 생략하고(장문 baseline 채점기라 숏폼에서 불안정) 스팬 스캔만으로 게이트 ①·⑤ + 채널 규칙을 적용한다.

### Phase 4 — 산출 (출력 계약)

- 발행본 전문 (마크다운 블록)
- 검증 결과 한 줄: `S1 {n} / S2 {n} / risk_band {band} / 게이트 {통과|실패 항목}`
- 사용한 실측 디테일 목록 (팩트체크용 — 수치·날짜·출처)
- 적용 프리셋·말투 명시
- 저장 경로: `_workspace/brtwritenotai/{run_id}/final.md`
- 제목 후보 2개 — blog/메인글만 (검색어 + 구체 숫자 형식, "완벽 정리" 류 수식어 금지). 숏폼 포맷은 생략.

## voice 모드 (Voice Card 생성/갱신)

- 입력: 사용자가 직접 쓴 글 샘플 3~5개 — **맥락을 섞어서**(블로그·공지·커뮤니티 글·카톡/메일). 한 종류만 들어오면 카드가 편향된다고 알리고 진행 여부를 확인한다.
- 추출: 문장 구조·어휘 선택·리듬·성격 → ① dos/don'ts ② "나 같은 문장 vs 아닌 문장" 대비 3쌍 ③ 사용자 목소리로 쓴 예문 3개.
- 저장: `_workspace/brtwritenotai/voice-card.md`. 이후 write/polish가 자동 적용한다(적용 우선순위는 `core/channels.md`). 사용자 글이 더 쌓이면 재생성을 권고한다(문체는 변한다).
