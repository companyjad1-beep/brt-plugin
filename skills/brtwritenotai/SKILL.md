# brtwritenotai — 처음부터 AI 티 없는 한국어 글쓰기 (하네스 진입점)

**최종 목적: 마케팅에 쓰는 모든 글을 AI 티 없이 사람이 쓴 것처럼 만든다.** `humanize-korean`(im-not-ai)은 이미 쓴 글의 티를 지우는 윤문기고, 이 스킬은 그 앞 단계 — 글을 만들 때부터 티를 안 만드는 생산 파이프라인이다. 이 문서는 진입점 전용이며 로직을 복제하지 않는다. **로직 변경은 core/에만 한다.**

`core/...` 경로는 전부 **이 SKILL.md가 있는 폴더 기준**으로 해석한다(뉴즈 레포·brt 플러그인·미러 어디서든 동일).

## 모드 → core 로드 맵 (필요한 것만 읽는다)

| 모드 | 커맨드 | 로드 순서 |
|---|---|---|
| write (기본) | `/brtwritenotai:write` | `core/pipeline.md` → `core/rulebook.md` → `core/channels.md` (+프리셋 지정·권장 시 `core/style-presets.md`) |
| polish | `/brtwritenotai:polish` | `core/eval.md` → `core/rulebook.md` |

| help | `/brtwritenotai:help` | 로드 없음 — 아래 치트시트 즉답 |

## Threads 운영 확장

`thread` 또는 `reply` 산출이면 `core/threads-ops.md`를 추가로 로드한다. 시간대·게시 후 60분·댓글 원정 규칙은 운영 기본값이며, 실제 계정 `ledger` 성과와 충돌하면 실측이 우선한다. 게시·댓글·팔로우는 사용자 승인 없이 실행하지 않는다.

## 하드 규칙 (모든 모드 공통)

- 사실을 지어내지 않는다. 실측 디테일이 없으면 만들지 말고 인터뷰로 받는다. **가짜 경험담·가짜 수치는 이 스킬의 존재 이유를 부정하는 최악의 실패다.**
- 고유명사·수치·날짜·직접 인용·업계 표준 영어 약어(API·LLM 등)는 탐지·수정 대상에서 제외.
- **사업 판단 비개입**: 상표·브랜드 노출 타이밍·법무·마케팅 전략 같은 사업 게이트는 이 스킬 범위 밖이다. 그런 이유로 집필을 막거나 경고를 얹지 않는다 — 발행 여부·시점은 사용자 몫.
- **프로액티브 플래그**: 이 스킬을 명시 호출하지 않았어도, 발행성 프로즈(마케팅 카피·알림 문구·블로그·공지)를 만들어 건넬 때는 전달 직전 셀프 스캔한다. S1 1건+ 또는 티 합계 3건+면 산출물 아래 한 줄로 플래그하고, 자동 재작성은 하지 않는다. 사용자가 직접 쓴 글은 요청 없이 스캔·플래그하지 않는다.
- newz 관련 글이면 브랜드 톤: 단정하되 근거 제시, 검수·보증 우위는 사실로만 어필, 경쟁사 비방 금지. (newz 무관 글이면 무시)
- 발행 채널이 네이버 블로그면 경험 신호(C-Rank/DIA)가 핵심이므로 실측·실화 비중을 더 높인다.

## help 치트시트 ("사용법 알려줘" 시 이것만 출력하고 끝)

> **brtwritenotai — AI 티 없는 마케팅 글쓰기**
> 블로그·인스타·쓰레드/X·메인글·답글. 주제 없으면 질문으로 발굴, 정보 부족하면 물어봄, 날조 0, 자체 채점 통과본만 산출.
>
> **호출 예시**
> - 글 쓰기: `/brtwritenotai:write 아이폰14 시세 글` (클로드코드) / "brtwritenotai로 아이폰14 시세 글 써줘" (GJC·코덱스·헤르메스) / 플러그인이면 `/brt:write`
> - 주제가 없으면: "블로그 글 아무거나" → 주제 발굴 질문부터 시작한다
> - 채널 지정: "…쓰레드용으로" / "…인스타 캡션으로" / "이 댓글에 답글 써줘"
> - 말투 지정: "…해요체로" / "…반말로" / "…합니다체로" / "…개조식으로" (안 쓰면 Voice Card → 채널 기본 순)
> - 문체 프리셋: "…팩트축적식으로"(분석·시세) / "…동료화법식으로"(커뮤니티) / "…사유전개식"(에세이) / "…체험일기식"(캐주얼 리뷰) / "…문제해소식"(비교) / "…안내문식"(공지) / "…판매카피식"(상세·랜딩)
> - 기존 글 다듬기: `/brtwritenotai:polish <글>` — 뭘 왜 바꿨는지 전부 보여준다
> - AI 티 검사만: `/brtwritenotai:check <글>` — 수정 없이 판정 + 티 밀도 버킷
> - 내 말투 등록: `/brtwritenotai:voice <내가 쓴 글 3~5개>` — 이후 write/polish에 자동 적용
>
> **결과물에 붙는 것**: 발행본 + 검증 한 줄(S1/S2/risk_band) + 사용한 실측 데이터 목록(팩트체크용) + 블로그면 제목 후보 2개
>
> **팁**: 실측 숫자·직접 겪은 일을 요청에 같이 주면 질문이 줄고 글이 세진다. 말투 매번 말하기 귀찮으면 voice로 한 번 등록.
