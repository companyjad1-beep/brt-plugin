# 초안→비평→개선 멀티패스 루프

이 문서는 사용자의 아이디어를 생성기별 최종 프롬프트로 수렴시키는 공통 코어 루프다. 모든 단계는 한국어로 수행하고, 생성기 호환을 위해 필요한 영어 용어만 괄호 또는 템플릿 필드명으로 병기한다. `holdout-eval/`은 어떤 경우에도 읽거나 참조하지 않는다.

## 1. 입력 해석

루프를 시작하기 전에 사용자 입력을 다음 항목으로 분해한다.

1. 피사체: 사람, 제품, 장소, 사건, 브랜드 요소, 유지해야 할 고유 특징.
2. 의도: 광고, 프로필, 상세페이지, 소셜 썸네일, 영상 클립, 편집 요청 등 결과물의 목적.
3. 도메인: 인물 마케팅, 제품 광고, 패션, 뷰티, 푸드, 공간, 교육, 영화적 장면 등.
4. 타깃 생성기: `gpt-image-2`, `nano-banana-pro`, `seedance-2` 중 하나.
5. 입력 확실성: 명시된 정보, 추정 가능한 정보, 부족한 정보.
6. 참고 자료: 참고 이미지 경로, 캐릭터 시트, 골든셋 예시, 레퍼런스 문서.

타깃 생성기가 명시되지 않으면 다음 기준으로 선택한다.

- 정지 이미지, 인물 또는 제품 광고, 텍스트 렌더링이 중요하면 `gpt-image-2`.
- 다중 참고 이미지, 긴 문맥, 레퍼런스 역할 분리가 중요하면 `nano-banana-pro`.
- 움직임, 타임라인, 카메라 무브먼트, 립싱크, 영상 참고가 중요하면 `seedance-2`.

해석 결과는 설계메모의 `interpretation`에 남긴다. 불확실한 추정은 단정하지 않고 `assumptions`에 적는다.

## 2. Few-shot 예시 주입 규칙

`golden-set/` 또는 `reference/`에 접근 가능한 예시가 있고 비어 있지 않다면, 유사 도메인 예시 1~2개만 컨텍스트에 포함한다.

- 예시는 현재 요청과 도메인, 피사체 유형, 출력 매체가 가까운 것만 고른다.
- 예시의 스타일을 그대로 복제하지 말고, 구조와 판단 기준만 참고한다.
- 예시에서 사용자 고유 정보, 브랜드명, 인물명, 파일 경로를 무단 차용하지 않는다.
- `holdout-eval/`은 평가 격리 영역이므로 절대 참조하지 않는다.

컨텍스트에 포함할 때는 다음처럼 짧게 요약한다.

```text
유사 예시 참고:
- 도메인: 인물 스킨케어 캠페인
- 유효했던 구조: 인물 외모 고정 → 제품 노출 → 카피 여백 → 조명/구도 → 금지 조건
- 현재 요청에 가져올 점: 제품 라벨 가독성과 얼굴 안정성 체크
```

## 3. 패스 구조

`designMemo.loopTrace`는 최소 3개 객체를 가진 배열이다. 각 객체는 `pass:number`, `type:draft|critique|improve`, `summary:string`, `weaknesses:string[]`, `changesApplied:string[]`만 기록한다. 기본 흐름은 draft → critique → improve이고, 비평에서 약점이 남으면 critique → improve를 최대 5개 항목까지 반복한다.

### 3.1 패스 1: 초안 작성

1. 입력 해석을 바탕으로 생성기별 템플릿을 선택한다.
2. `core/generators/gpt-image-2.md`, `core/generators/nano-banana-pro.md`, `core/generators/seedance-2.md`의 해당 템플릿 순서를 따른다.
3. 누락된 정보는 과도하게 창작하지 않고, 필요한 최소 가정만 반영한다.
4. 프롬프트 본문에는 피사체, 행동, 장면, 구도/카메라, 조명, 스타일, 텍스트, 제약을 가능한 한 명시한다.

생성기별 기본 골격:

- `gpt-image-2`: `Subject / Action / Scene / Composition / Lighting / Style / Text Constraint / Constraints`.
- `nano-banana-pro`: `Reference Roles / Identity Header / Subject / Composition / Action / Location / Style / Camera & Lighting / Typography / Hard Negative`.
- `seedance-2`: `Subject → Action → Environment → Camera → Style → Constraints`, 필요 시 `[0s] [3s] [6s]` 또는 `Shot 1/2/3`.

### 3.2 자기비평

자기비평에서는 체크리스트 관점으로 실제 약점만 찾는다. 약점이 있으면 핵심 약점 3~6개를 기록하되, 약점이 0개이면 억지로 약점 3개를 만들지 않는다. 이 경우 `summary`에 `약점 없음 확인`을 명시하고 `weaknesses: []`로 기록한다.
비평 관점:

1. 피사체 구체성: 주 피사체와 고유 특징이 충분히 선명한가.
2. 구도: 프레이밍, 여백, 배치, 종횡비가 결과 목적에 맞는가.
3. 카메라: 앵글, 렌즈감, 영상이면 카메라 움직임이 명확하고 충돌하지 않는가.
4. 조명: 방향, 색온도, 대비, 질감이 명시되어 있는가.
5. 스타일: 추상적 품질어가 아니라 매체, 마감, 색감, 브랜드 톤으로 적혔는가.
6. 제약 누락: 얼굴, 손, 제품, 텍스트, 워터마크, 로고, 왜곡 방지 조건이 빠지지 않았는가.

체크리스트 판정 어휘는 `충족`, `부분 충족`, `미달`, `판정 불가`만 사용한다.

약점 없음이 확인되어도 `designMemo.loopTrace` 최소 3항목은 유지한다. draft 다음 critique에서 바로 약점이 0개이면, 세 번째 항목은 `type: improve`로 두고 `changesApplied`에 `변경 없음: 약점 없음 확인 후 최종화`를 기록한다.

```text
비평 예시:
- 피사체 구체성: 부분 충족 — 인물의 나이대와 헤어는 있으나 얼굴형과 고유 마커가 부족하다.
- 구도: 미달 — 제품과 카피 여백의 위치가 지정되지 않았다.
- 조명: 부분 충족 — 부드러운 조명은 있으나 광원 방향과 색온도가 빠졌다.
```

### 3.3 개선

개선은 비평에서 지적한 약점만 수정한다.

- 유지할 부분: 이미 충족된 피사체, 장면, 스타일, 문구, 제약.
- 수정할 부분: `부분 충족`, `미달`, `판정 불가` 항목과 직접 연결된 문장.
- 금지: 전면 재작성, 도메인 변경, 타깃 생성기 변경, 사용자가 지정한 문구 변경, 검증되지 않은 레퍼런스 추가.
- 권장: 한 패스에서 3~6개 핵심 문장만 보강한다.

개선 이유는 설계메모의 `changePoints`와 `loopTrace`에 남긴다.

## 4. 수렴 조건

다음 조건을 모두 만족하면 루프를 종료한다.

1. `designMemo.loopTrace`가 최소 3개 항목을 포함한다.
2. 마지막 critique 항목에서 `weaknesses`가 빈 배열이거나, 마지막 improve 항목 이후 체크리스트 전 항목이 `충족`이다.
3. 사용자 의도, 타깃 생성기, 주요 제약이 최종 프롬프트에 남아 있다.
4. 개선 과정에서 전면 재작성이나 의미 변경이 발생하지 않았다.

세 번째 항목 이후에도 약점이 남으면 최대 5개 항목까지 critique → improve를 반복한다. 5개 항목 후에도 약점이 남는 경우, 남은 약점을 `assumptions` 또는 `checklistResults`에 명시하고 최종본을 `provisional` 성격으로 다룬다.

## 5. 패스 흔적 기록 규칙

각 패스는 설계메모용 흔적을 남긴다. 긴 초안 전체를 반복 저장하지 말고, 판단에 필요한 요약을 남긴다.

```text
loopTrace:
- pass: 1
  type: draft
  summary: 최초 해석에 따라 GPT Image 2 템플릿으로 인물 스킨케어 광고 초안을 작성했다.
  weaknesses: []
  changesApplied: []
- pass: 2
  type: critique
  summary: 체크리스트 기준으로 초안을 점검했고 제품 라벨 위치, 카피 여백, 손/제품 제약 약점을 확인했다.
  weaknesses:
    - 제품 라벨 위치와 카피 여백이 없다.
    - 손 기형과 제품 왜곡 방지 제약이 없다.
    - 조명 방향과 색온도가 아직 약하다.
  changesApplied: []
- pass: 3
  type: improve
  summary: 비평에서 확인한 약점만 보강해 최종 프롬프트로 수렴시켰다.
  weaknesses: []
  changesApplied:
    - 제품 라벨이 정면 70% 이상 보이도록 위치를 고정했다.
    - 오른쪽 상단 카피 여백과 손/제품 왜곡 방지 제약을 추가했다.
    - 카메라 왼쪽 소프트 키 라이트와 따뜻한 뉴트럴 톤을 추가했다.
```

최종 산출물의 `designMemo.loopTrace`에는 각 객체마다 `pass`, `type`, `summary`, `weaknesses`, `changesApplied`를 포함한다. 체크리스트 판정은 `checklistResults`에 따로 기록하고 `loopTrace` 객체 안에 중복 저장하지 않는다.

## 6. 최종 산출 규칙

루프가 끝나면 다음을 함께 산출한다.

1. 최종 프롬프트 본문 `finalText`.
2. 설계메모 `designMemo`.
3. 필수 변형 2개 이상 `variants`: 같은 의도를 유지하되 톤, 구도, 무드 중 하나만 바꾼다.
4. 필요 시 참고 이미지 경로 `referenceImagePaths`.
5. 체크리스트 결과 `checklistResults`.

변형은 최종본을 흔들지 않는 범위에서 만든다. 인물 정체성, 제품명, 정확한 이미지 내 문구, 핵심 제약은 변형에서도 유지한다.

## 7. finalText 위생·문체 규칙 (2026-07-08 블라인드 벤치 식별 단서 교정)

축소 블라인드 벤치(reference 9 vs 하네스 9)에서 심판이 100% 식별한 단서를 근거로 다음을 강제한다.

- 본문 무경로: `finalText`와 `variants[].text` 안에 로컬 파일 경로(workspace/... 등)를 쓰지 않는다. 참조 이미지는 "첨부한 첫 번째 이미지", "@ref1(첫 번째 첨부)"처럼 첨부 순서로 서술하고, 경로는 `referenceImagePaths`에만 둔다.
- 실행 파라미터 분리: `n=6`, 종횡비 지시 접미사 같은 실행 파라미터를 본문에 넣지 않는다. 실행 메모는 designMemo 또는 별도 안내로 전달한다.
- 내부 메모 금지: "리허설 전용", "가상 참고이미지" 같은 하네스 내부 표기를 본문에 남기지 않는다.
- 표제 비노출(gpt-image-2 한국어 자연문형): Subject/Scene/Constraints류 템플릿 표제는 조립용 골격일 뿐, 최종 문안에서는 같은 순서를 유지한 채 자연문으로 녹인다. nano-banana-pro 영문 구조형은 표제가 생성기 제어 관행이므로 유지하되, 이 표제가 블라인드 평가에서 식별 단서가 됨을 인지한다.
- 닫는 문장 밀도: 축별 항목을 평평하게 나열하지 말고, 앞 요소를 받아 다음 요소로 잇는 연결 문장으로 쓴다. 나쁜 예: "조명: 하드 키. 재질: 새틴. 팔레트: 3색." / 좋은 예: "우상단에서 떨어진 하드 키가 새틴의 방향성 하이라이트를 긴 띠로 세우고, 팔레트는 크림·그레이·블랙 3색 안에서 닫힌다."
- 부재 근육 보강 검토: 서사 네거티브(결말 선공개 금지류), 정체성 고정 규칙과 우발 변주 규칙의 분리 선언, 영상의 초 단위 카메라 타임라인 — 골든셋 대비 하네스 산출물에 반복적으로 없다고 지목된 축이며, 해당 도메인 요청에서 우선 검토한다.
