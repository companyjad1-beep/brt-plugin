# 설계메모 규격

설계메모는 최종 프롬프트가 왜 그렇게 작성되었는지 설명하는 동반 문서다. 사용자가 나중에 수정할 수 있도록 해석, 선택 이유, 가정, 변경 가능한 지점, 변형, 루프 흔적을 짧고 명확하게 남긴다.

## 1. 기본 원칙

- 한국어로 작성한다.
- 확정 사실과 가정을 분리한다.
- 과장된 창작 의도를 쓰지 말고 실제 프롬프트 선택 이유를 쓴다.
- 사용자가 바로 손댈 수 있는 항목을 드러낸다.
- 루프에서 무엇을 고쳤는지 추적 가능해야 한다.
- 프롬프트 스키마에서는 `designMemo` 객체에 `interpretation`, `keyChoices`, `assumptions`, `changePoints`, `loopTrace`만 넣고, 변형 버전은 최상위 `variants[]`에 둔다.

## 2. 필수 구조

설계메모는 사람이 읽는 출력에서 다음 섹션을 반드시 포함한다.

```text
설계메모
1. 해석
2. 핵심 선택
3. 가정
4. 변경 포인트
5. 변형 버전 설명
6. 루프 흔적 요약
```

스키마에 저장할 때는 다음 필드에 매핑한다.

```text
designMemo:
  interpretation: ""
  keyChoices: ""
  assumptions: []
  changePoints: []
  loopTrace: []
variants:
  - label: ""
    text: ""
```

## 3. 해석: 입력을 어떻게 읽었나

`interpretation`에는 사용자 입력을 어떤 요청으로 이해했는지 적는다.

포함 항목:

- 주 피사체.
- 목적 또는 사용처.
- 도메인.
- 타깃 생성기.
- 핵심 제약.
- 참고 이미지나 캐릭터 시트 사용 여부.

예시:

```text
사용자 입력을 30대 한국인 여성 창업자가 스킨케어 제품을 들고 있는 세로형 런칭 광고 이미지 요청으로 해석했다. 목적은 소셜 광고와 상세페이지 히어로 컷이며, 텍스트 렌더링과 인물 안정성이 중요하므로 gpt-image-2를 타깃 생성기로 선택했다.
```

## 4. 핵심 선택: 왜 이 구도/조명/스타일인가

`keyChoices`에는 결과 품질을 좌우하는 주요 선택과 이유를 적는다.

포함 항목:

- 구도 선택: 인물 위치, 제품 위치, 여백, 종횡비.
- 카메라 선택: 샷 크기, 앵글, 렌즈 느낌, 영상이면 카메라 움직임.
- 조명 선택: 광원 방향, 색온도, 대비, 피부/제품 표현.
- 스타일 선택: 매체, 마감, 브랜드 톤.

예시:

```text
4:5 세로 포스터와 우측 1/3 인물 배치를 선택해 좌측 상단에 헤드라인 여백을 확보했다. 아이레벨 미디엄 클로즈업은 얼굴 신뢰감과 제품 노출을 동시에 잡기 쉽다. 카메라 왼쪽의 부드러운 키 라이트와 따뜻한 뉴트럴 톤은 스킨케어 제품의 깨끗하고 편안한 브랜드 톤에 맞다.
```

## 5. 가정: 2차 근거와 미확인 항목

`assumptions`에는 사용자 입력에 없어서 추정한 항목을 배열로 적는다. 2차 자료 기반 정보, 모델 가용성, 확인되지 않은 브랜드 규칙도 여기에 둔다.

규칙:

- 가정은 사실처럼 쓰지 않는다.
- 결과에 큰 영향을 주는 가정부터 적는다.
- 사용자가 바꾸면 어떤 부분이 달라지는지 짧게 덧붙인다.

예시:

```text
assumptions:
  - "브랜드 컬러가 제공되지 않아 크림·세이지·원목 팔레트를 기본 웰니스 톤으로 가정했다."
  - "정확한 제품 패키지 이미지가 없으므로 라벨 형태는 일반적인 세럼 병으로 가정했다."
  - "모델 가용성과 텍스트 정확도 정보는 2차 근거 기반 운영 메모이며 실제 생성 전 검수가 필요하다."
```

## 6. 변경 포인트: 사용자가 손대기 쉬운 지점

`changePoints`에는 사용자가 쉽게 수정할 수 있는 변수를 적는다.

권장 항목:

- 종횡비와 플랫폼.
- 헤드라인 문구와 위치.
- 피사체 의상.
- 배경 장소.
- 조명 톤.
- 제품 노출 크기.
- 카메라 샷 크기 또는 움직임.
- 네거티브 제약 강도.

예시:

```text
changePoints:
  - "헤드라인 문구: \"피부가 쉬는 시간\"을 캠페인 카피에 맞게 교체 가능."
  - "구도: 좌측 카피 여백이 필요 없으면 인물을 중앙 대칭 구도로 바꿀 수 있음."
  - "조명: 더 고급스럽게 보이려면 하이키에서 로우키+림 라이트 조합으로 변경 가능."
```

## 7. 변형 버전 설명

변형 버전 설명은 최상위 `variants[]`의 `label`과 `text`에 담는다. 사람이 읽는 설계메모에서는 각 변형이 무엇을 바꾸는지 한 줄 설명으로 붙인다.

규칙:

- 변형은 원본 의도와 핵심 제약을 유지한다.
- 한 변형에서 바꾸는 축은 1개가 원칙이다.
- 인물 정체성, 제품명, 정확한 이미지 내 문구, 필수 금지 조건은 유지한다.
- 변형 설명은 `designMemo.keyChoices`를 반복하지 말고, 원본 대비 차이만 적는다.

예시:

```text
variants:
  - label: "더 친근한 UGC 톤"
    text: "스튜디오 광고 느낌을 줄이고 욕실 자연광과 손동작을 강조한 버전. 인물 정체성, 제품 라벨, 카피 문구는 유지한다."
  - label: "더 프리미엄한 에디토리얼 톤"
    text: "배경을 절제하고 림 라이트와 저채도 색감으로 고급스러움을 강화한 버전. 핵심 제약은 원본과 같다."
```

## 8. 루프 흔적 요약

`loopTrace`에는 초안→비평→개선 과정의 핵심 흔적을 남긴다.

각 항목 필드:

```text
loopTrace:
  - pass: 1
    type: "draft"
    summary: ""
    weaknesses: []
    changesApplied: []
  - pass: 2
    type: "critique"
    summary: ""
    weaknesses: []
    changesApplied: []
  - pass: 3
    type: "improve"
    summary: ""
    weaknesses: []
    changesApplied: []
```

작성 규칙:

- 최소 3패스를 기록한다.
- 비수렴 패스의 `weaknesses`에는 체크리스트 관점의 약점을 3개 이상 적는다.
- `changesApplied`에는 실제로 바꾼 문장 또는 지시의 종류를 적는다.
- 마지막 패스가 수렴했다면 `weaknesses: []`로 둔다.
- 초안 전체를 반복 저장하지 말고 판단에 필요한 변화만 요약한다.

예시:

```text
loopTrace:
  - pass: 1
    type: "draft"
    summary: "인물 스킨케어 광고 초안을 GPT Image 2 템플릿으로 작성했다."
    weaknesses:
      - "제품 라벨 위치가 명확하지 않았다."
      - "손 기형 방지 제약이 부족했다."
      - "카피 여백의 위치가 빠졌다."
    changesApplied: []
  - pass: 2
    type: "critique"
    summary: "체크리스트 관점으로 초안을 비평해 제품 위치, 손 제약, 카피 여백 약점을 확정하고 해당 항목을 보강했다."
    weaknesses:
      - "조명 방향과 색온도가 아직 약했다."
      - "스타일이 추상적이라 매체와 마감 설명이 부족했다."
      - "렌즈감과 심도 지시가 약해 제품과 얼굴의 시선 우선순위가 불명확했다."
    changesApplied:
      - "제품 라벨이 카메라를 향하도록 수정했다."
      - "좌측 상단 카피 여백을 추가했다."
  - pass: 3
    type: "improve"
    summary: "조명, 스타일 마감, 렌즈감을 보강해 수렴했다."
    weaknesses: []
    changesApplied:
      - "카메라 왼쪽 소프트 키 라이트와 약한 필 라이트를 추가했다."
      - "자연스러운 50mm 렌즈 느낌과 얕은 심도를 추가했다."
```

## 9. 최종 점검

설계메모를 제출하기 전 다음을 확인한다.

- 해석에 피사체, 목적, 도메인, 타깃 생성기가 들어 있다.
- 핵심 선택에 구도, 조명, 스타일의 이유가 들어 있다.
- 가정이 1개 이상 있으면 미확인 항목임을 분명히 했다.
- 변경 포인트는 사용자가 실제로 바꿀 수 있는 단위다.
- 변형 설명은 최상위 `variants[]`에 있고 원본과 무엇이 다른지 한 줄로 이해된다.
- 루프 흔적은 최소 3패스이며 마지막 상태가 수렴 또는 보류로 명확하다.
