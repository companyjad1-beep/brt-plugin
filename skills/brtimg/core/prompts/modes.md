# 모드 규칙

이 문서는 프롬프트 생성 에이전트가 사용할 4가지 작업 모드와 조합 규칙을 정의한다. 모든 모드는 같은 출력 계약을 공유한다: 최종 프롬프트, 설계메모, 필수 변형 2개 이상, 참고 이미지 반영 내역, 체크리스트 결과를 남긴다.

## 1. 공통 모드 선택 결정 트리

사용자가 모드를 지정하지 않으면 다음 순서로 판정한다.

1. 피사체, 즉 누가 또는 무엇을 만들지 식별할 수 없으면 `conversational`을 선택한다. 첫 질문은 반드시 피사체를 좁히는 질문이다.
   - 예: "광고 이미지 만들어줘"처럼 인물, 제품, 공간 중 무엇인지 없으면 `conversational`.
2. 피사체는 명확하지만 톤, 무드, 스타일, 컨셉 방향이 2개 이상 자연스럽게 가능하면 `multi3`를 선택한다.
   - 예: "신제품 텀블러 광고"처럼 제품은 명확하지만 프리미엄, UGC, 라이프스타일 중 방향이 열려 있으면 `multi3`.
3. 피사체와 방향이 모두 명확하면 `oneshot`을 선택한다.
   - 예: "검은 세라믹 텀블러를 미니멀한 하이키 스튜디오 광고 사진으로"처럼 대상과 스타일 방향이 닫혀 있으면 `oneshot`.
4. 참고 이미지, 영상, 프레임, 스크린샷, 오디오 설명이 첨부되면 위 1~3의 판정 결과에 항상 `multimodal`을 병합한다.
   - 예: "첨부한 제품 사진을 참고해서 프리미엄 상세페이지 컷"이면 `oneshot + multimodal`.

모드명은 단일 선택이 아니라 조합될 수 있다. 예: `multimodal + conversational`, `multi3 + multimodal`, `oneshot + multimodal`.

## 2. oneshot 모드

`oneshot`은 사용자의 입력이 충분할 때 자동으로 한 번의 작업 흐름을 완주하는 기본 모드다.

### 실행 규칙

1. 입력을 해석해 피사체, 의도, 도메인, 타깃 생성기를 정한다.
2. 초안→비평→개선 루프를 `designMemo.loopTrace` 최소 3항목으로 수행한다.
3. 최종본 1개를 작성한다.
4. 설계메모를 작성한다.
5. 필수 변형 2개 이상을 작성한다.
6. 체크리스트 결과를 붙인다.

### 출력 규칙

- 최종본은 곧바로 생성기에 넣을 수 있는 형태여야 한다.
- 변형 2개 이상은 원본의 핵심 의도를 유지하되 하나의 해석축만 바꾼다.
- 설계메모에는 왜 이 구도, 조명, 스타일을 선택했는지 적는다.

변형 예시:

```text
변형 A: 더 밝은 하이키 뷰티 광고 톤
변형 B: 더 차분한 다큐멘터리 브랜드 필름 톤
```

## 3. multi3 모드

`multi3`는 사용자가 아직 방향을 고르지 않았을 때 서로 다른 해석 후보 3개를 먼저 제시하는 모드다.

### 후보 생성 규칙

세 후보는 다음 해석축 중 최소 2개 이상이 서로 달라야 한다.

- 톤: 프리미엄, 친근한 UGC, 시네마틱, 미니멀, 럭셔리 등.
- 구도: 클로즈업, 미디엄 샷, 전신, 제품 중심, 인물 중심 등.
- 무드: 따뜻함, 전문성, 긴장감, 편안함, 미래적 느낌 등.
- 컨셉: 창업자 메시지, 제품 사용 장면, 라이프스타일 컷, 캠페인 포스터 등.

각 후보에는 해석 라벨 1줄을 붙인다.

```text
후보 1 — 프리미엄 창업자 캠페인: 신뢰감 있는 인물 중심 구도와 카피 여백을 우선한다.
후보 2 — 제품 사용 UGC: 손과 제품 상호작용을 가까이 보여주고 친근한 플랫폼 광고처럼 만든다.
후보 3 — 시네마틱 브랜드 필름: 공간, 조명, 느린 카메라 움직임으로 브랜드 무드를 강조한다.
```

### 사용자 선택 후 규칙

- 사용자가 선택한 후보만 루프에 넣는다.
- 선택되지 않은 후보의 문장, 제약, 스타일을 섞지 않는다.
- 선택 후에는 `oneshot`과 같은 방식으로 `designMemo.loopTrace` 최소 3항목 루프를 수행한다.
- 후보 단계에서는 최종 프롬프트처럼 과도하게 상세하게 쓰지 말고, 선택 가능한 방향성이 보이도록 압축한다.

## 4. conversational 모드

`conversational`은 부족 정보가 결과 품질을 크게 흔들 때 질문을 통해 정보를 보강하는 모드다.

### 질문 규칙

- 한 번에 질문 1개만 한다.
- 최대 3라운드까지만 질문한다.
- 사용자가 답하지 않아도 진행 가능한 기본 가정을 준비한다.
- 질문은 선택지를 포함해 답하기 쉽게 만든다.

### 질문 우선순위

1. 피사체: 누구 또는 무엇을 그릴 것인가.
2. 용도/플랫폼: 광고, 상세페이지, 인스타그램, 유튜브 썸네일, 영상 클립 등.
3. 무드: 프리미엄, 친근함, 시네마틱, 귀여움, 전문성 등.
4. 디테일: 의상, 제품 색, 문구, 배경, 종횡비 등.

예시:

```text
질문 1: 주 피사체는 사람, 제품, 공간 중 무엇인가요? 이미 정한 브랜드나 제품명이 있으면 함께 알려주세요.
```

3라운드 후에도 정보가 부족하면 남은 추정을 설계메모의 `assumptions`에 적고 루프를 진행한다.

## 5. multimodal 모드

`multimodal`은 참고 이미지, 영상, 프레임, 스크린샷, 오디오 설명이 있을 때 적용한다.

### 참고 이미지 분석 규칙

참고 이미지를 다음 항목으로 분해한다.

1. 구도: 샷 크기, 앵글, 여백, 피사체 배치.
2. 조명: 광원 방향, 밝기, 대비, 색온도.
3. 색: 팔레트, 채도, 배경색, 브랜드 컬러.
4. 스타일: 사진, 광고, 에디토리얼, UGC, 영화적 질감, 일러스트 등.
5. 인물 특징: 얼굴형, 헤어, 눈, 피부 톤, 체형, 고유 마커, 의상.
6. 제품 특징: 형태, 재질, 라벨 위치, 크기, 로고, 패키지 비율.

분석한 내용은 프롬프트에 직접 반영하되, 참고 이미지가 제어하는 역할을 분리한다.

- 아이덴티티 참고: 얼굴과 고유 닮음만 제어.
- 포즈 참고: 자세와 손 위치만 제어.
- 스타일 참고: 색감, 조명, 마감만 제어.
- 환경 참고: 배경 공간과 소품 밀도만 제어.

### 영상 참고 규칙

영상 참고는 원본 영상을 그대로 인용하지 않고, 프레임 또는 설명 기반으로 변환한다.

- 대표 프레임: 시작, 중간, 종료 상태를 2~3개로 요약한다.
- 동작: 피사체 움직임과 카메라 움직임을 분리한다.
- 리듬: 느림, 안정적, 점진적, 반복적 등 관찰 가능한 말로 적는다.
- 금지: 영상 속 인물의 정체성을 무단 복제하거나, 허용되지 않은 브랜드 요소를 가져오지 않는다.

## 6. 모드 조합 규칙

### multimodal + conversational

참고 자료는 있지만 의도나 용도가 불명확할 때 사용한다.

1. 먼저 참고 이미지를 분석한다.
2. 분석만으로 결정할 수 없는 가장 중요한 정보 1개를 질문한다.
3. 최대 3라운드 후 루프를 진행한다.
4. 설계메모에는 `참고 이미지에서 확인한 내용`과 `사용자 답변으로 확정한 내용`을 분리한다.

### multimodal + oneshot

참고 이미지와 요청이 충분히 구체적일 때 사용한다.

1. 참고 이미지 역할을 선언한다.
2. 생성기별 참조 이미지 지시문으로 변환한다.
3. 루프를 자동 완주한다.
4. 최종본에는 참고 이미지 보존 제약을 반드시 포함한다.

### multimodal + multi3

참고 이미지는 있지만 해석 방향이 여러 갈래일 때 사용한다.

1. 세 후보 모두 같은 참고 이미지 사실을 공유한다.
2. 후보마다 톤, 구도, 무드, 컨셉 중 다른 축을 제안한다.
3. 사용자가 선택한 후보만 참고 이미지 지시문과 함께 루프에 넣는다.

### multi3 + conversational

입력이 지나치게 넓고 후보 3개도 임의적일 때 사용한다.

1. 질문 1개로 피사체 또는 용도를 먼저 좁힌다.
2. 답변을 받은 뒤 후보 3개를 제시한다.
3. 선택된 후보만 루프에 넣는다.

## 7. 충돌 해결

- 사용자가 명시한 모드가 있으면 사용자 지정이 우선한다.
- 참고 이미지가 있으면 `multimodal` 규칙을 반드시 병행한다.
- 질문 필요성과 자동 완주가 충돌하면, 결과를 크게 바꾸는 정보만 질문하고 나머지는 가정한다.
- `seedance-2` 영상 요청에서는 카메라 움직임을 한 샷에 하나만 둔다.
- 생성기 템플릿과 모드 규칙이 충돌하면 생성기 템플릿을 우선하고, 모드 규칙은 흐름 제어에만 사용한다.
