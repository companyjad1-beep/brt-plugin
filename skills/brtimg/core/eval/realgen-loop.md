# 실생성 평가 루프

수집일: 2026-07-07

## 1. 목적

실생성 평가 루프는 프롬프트를 실제 이미지·영상 생성기에 투입하고, 산출된 결과물을 기준으로 품질을 판정하는 3층 평가의 마지막 층이다. 앞 단계에서 문장 규칙, 체크리스트, 정적 평가를 통과했더라도 실제 생성 결과가 요구 의도와 어긋날 수 있으므로, 이 단계는 결과 이미지·영상 또는 대표 프레임을 멀티모달(multimodal)로 검토해 최종 적합성을 판단한다.

평가 목표는 다음과 같다.

- 최종 프롬프트가 대상 생성기에서 의도한 장면, 스타일, 구도, 제약을 재현하는지 확인한다.
- 체크리스트 미달 항목을 근거로 프롬프트를 수정한다.
- 자동 또는 수동 반복을 최대 3회까지 수행해 개선 여부를 기록한다.
- 결과와 판단 근거를 eval-report로 남겨 이후 회귀 평가와 비교가 가능하게 한다.

## 2. 경로 A — MCP 자동 루프

MCP(Model Context Protocol) 도구가 세션에서 감지되고, 사용자가 자동 루프를 허용하면 경로 A를 사용한다. 이 경로는 하네스가 사용 가능한 이미지 생성 MCP 도구를 통해 프롬프트 전달, 결과 수신, 평가, 개선, 재생성을 한 흐름으로 수행하는 방식이다.

리서치 근거상 MCP 생태계에는 이미지 생성 MCP 서버가 다수 존재하지만, 이 하네스의 자동 호출 대상은 GPT Image 2.0, Nano Banana Pro, Seedance 2.0 세 타겟 생성기에 한정한다. 예시는 다음과 같다.

- [lansespirit/image-gen-mcp](https://github.com/lansespirit/image-gen-mcp): gpt-image-2, gpt-image-1.5, DALL-E, Imagen 4 계열 지원을 표방하는 이미지 생성 MCP 서버. 해당 서버가 복수 모델을 표방하더라도 본 하네스는 타겟 3종 도구만 사용하며, DALL-E/Imagen 등 다른 모델은 호출하지 않는다.
- [shinpr/mcp-image](https://github.com/shinpr/mcp-image): Nano Banana Pro 및 GPT Image 계열 사용을 표방하는 이미지 생성 MCP 서버. 본 하네스는 타겟 생성기와 일치하는 도구만 후보로 삼는다.
- [qhdrl12/mcp-server-gemini-image-generator](https://github.com/qhdrl12/mcp-server-gemini-image-generator): Gemini 이미지 생성 연동을 표방하는 MCP 서버. 본 하네스는 Nano Banana Pro 타겟과 맞는 도구만 사용한다.

또한 OpenAI와 Google 모두 2026년 기준 네이티브 MCP 지원 흐름을 제공하므로, 이미지 생성 도구가 MCP 형태로 노출되는 환경을 우선 탐색할 수 있다. 단, MCP 서버별 지원 모델, 입력 필드, 인증 방식, 출력 형식은 달라질 수 있으므로 하네스는 특정 서버 구현에 고정되지 않고 현재 세션에 실제 등록된 타겟 3종 도구 목록을 기준으로 동작해야 한다. 이 문단은 타 생성기 어댑터 추가를 허용하는 근거가 아니다.

경로 A의 완주 절차는 다음과 같다.

1. 세션 시작 시 사용 가능한 MCP 도구 목록에서 이미지 생성 기능을 탐색한다.
2. 도구 설명, 입력 스키마, 지원 모델명을 확인해 현재 프롬프트를 전달할 수 있는 후보를 고른다.
3. 후보가 여러 개이면 대상 생성기, 모델, 출력 형식, 비용·제한 정보를 사용자에게 간단히 제시하고 기본 후보를 제안한다.
4. 최종 프롬프트와 필요한 파라미터를 MCP 이미지 생성 도구에 전달한다.
5. 생성 결과 이미지 또는 파일 참조를 수신한다.
6. 하네스가 결과 이미지를 멀티모달로 분석해 체크리스트와 대조한다.
7. 각 체크 항목을 `충족`, `부분 충족`, `미달`, `판정 불가`로 판정하고 근거를 적는다.
8. 미달 또는 부분 충족 항목이 있으면 해당 항목만 반영해 프롬프트를 개선한다.
9. 개선 프롬프트로 재생성한다. 재생성은 최초 생성을 포함해 최대 3회까지 수행한다.
10. 가장 적합한 결과, 반복별 판단, 최종 프롬프트, 남은 한계를 eval-report에 기록한다.

경로 A는 MCP 도구가 준비된 경우 사용자가 이미지 파일을 수동으로 옮기지 않아도 단독 완주할 수 있어야 한다. 다만 도구 호출 실패, 모델 미지원, 결과 파일 수신 실패, 권한 문제, 사용자의 자동 생성 거부가 발생하면 오류로 중단하지 않고 경로 B로 자연스럽게 전환한다.

## 3. 경로 B — 수동 복붙 루프

경로 B는 기본 경로이자 모든 환경의 폴백(fallback) 경로다. MCP 도구가 없거나, 사용자가 자동 루프를 거부하거나, 대상 생성기가 MCP로 안정적으로 제공되지 않는 경우 하네스는 최종 프롬프트를 복사 가능한 블록으로 출력하고 사용자가 생성기 앱 또는 웹에서 직접 실행한다.

특히 Seedance 계열 영상 생성은 이 경로를 기본으로 한다. 2026년 기준 Seedance 전용 MCP는 보편화되지 않았고, BytePlus ModelArk API 기반 커뮤니티 서버는 존재 여부와 품질, 인터페이스가 가변적이다. 따라서 영상 생성 평가는 API 키 직접 호출이나 브라우저 자동화 없이 사용자가 생성기에서 직접 실행한 결과 영상 또는 대표 프레임 캡처를 대화에 첨부하는 방식을 표준으로 삼는다.

경로 B의 완주 절차는 다음과 같다.

1. 하네스가 최종 프롬프트를 복사 가능한 코드 블록으로 출력한다.
2. 필요한 경우 생성기별 실행 메모를 함께 제공한다. 예: 모델명, 화면비, 길이, 스타일 강도, 금지어 입력 위치.
3. 사용자가 생성기 앱 또는 웹 UI에 프롬프트를 붙여넣고 실행한다.
4. 사용자가 결과 이미지, 결과 영상, 또는 영상 대표 프레임 캡처를 대화에 첨부한다.
5. 하네스가 첨부 결과물을 멀티모달로 분석한다.
6. 체크리스트와 대조해 `충족`, `부분 충족`, `미달`, `판정 불가`로 판정하고 근거를 적는다.
7. 미달 또는 부분 충족 항목을 해결하는 개선안과 수정 프롬프트를 제시한다.
8. 사용자가 수정 프롬프트를 다시 생성기에 적용하고 결과물을 첨부한다.
9. 반복은 최초 결과 평가를 포함해 최대 3회까지 수행한다.
10. 가장 적합한 결과, 반복별 판단, 최종 프롬프트, 남은 한계를 eval-report에 기록한다.

경로 B는 MCP 도구가 전혀 없는 세션에서도 단독 완주할 수 있어야 한다. 하네스의 역할은 프롬프트 출력, 결과물 판독, 체크리스트 대조, 개선 프롬프트 작성, 평가 기록이며, 생성기 조작은 사용자가 직접 수행한다.

## 4. 경로 선택 규칙

세션 시작 시 하네스는 MCP 도구 존재 여부를 확인한다.

- 이미지 생성 MCP 도구가 있으면 경로 A를 제안한다. 사용자는 자동 생성 대신 경로 B를 선택할 수 있다.
- MCP 도구가 없으면 경로 B로 자동 폴백한다.
- MCP 도구는 있으나 대상 생성기와 맞지 않거나 호출이 실패하면 경로 B로 전환한다.
- Seedance 등 영상 생성은 전용 MCP가 명확히 준비된 예외 상황을 제외하고 경로 B를 기본값으로 사용한다.
- 경로 전환은 실패로 취급하지 않는다. 사용자는 동일한 체크리스트와 동일한 반복 한도 안에서 평가를 계속한다.

경로 선택 메시지는 짧고 실행 가능해야 한다. 예를 들어 MCP가 있으면 “이미지 생성 MCP 도구가 감지되었습니다. 자동 루프로 생성·평가를 진행할 수 있으며, 원하면 수동 복붙 루프로 진행합니다.”처럼 안내한다. MCP가 없으면 “자동 생성 도구가 감지되지 않아 수동 복붙 루프로 진행합니다.”처럼 안내하고 즉시 복사 블록을 제공한다.

## 5. 평가 기록

평가 결과는 `core/schema/eval-report.schema.json` 규격을 따른 `eval-report`로 `workspace/reports/` 아래에 저장한다.

기록에는 최소한 다음 정보가 포함되어야 한다.

- 평가 대상 프롬프트와 최종 수정 프롬프트.
- 사용 경로: `A-mcp` 또는 `B-manual`.
- 사용 생성기, 모델, MCP 서버 또는 수동 실행 환경.
- 반복 번호와 각 반복의 입력 프롬프트.
- 결과물 참조: 이미지 파일, 영상 파일, 대표 프레임, 또는 사용자가 첨부한 대화 내 참조.
- 체크리스트 항목별 판정과 근거.
- 미달 항목에 대한 수정 방향.
- 최종 채택 결과와 남은 한계.
- 판정 일시와 수집·평가에 사용한 리서치 기준일.

`workspace/reports/`는 평가 산출물 저장 위치이며, core 문서는 프롬프트 로직·체크리스트·템플릿의 원천만 보관한다.

## 6. 금지

다음 행위는 실생성 평가 루프에서 금지한다.

- 브라우저 자동화로 생성기 웹 UI를 조작하지 않는다. 자산관리 UI와 브라우저 자동화는 비목표다.
- API 키를 받아 생성기 API를 직접 호출하지 않는다. OAuth 구독 기반 CLI 전용 설계를 유지하며 API 키 기반 독립 앱처럼 동작하지 않는다.
- 프롬프트 로직, 체크리스트, 템플릿을 core 밖에 중복 정의하지 않는다.
- MCP가 없다는 이유로 평가를 실패 처리하지 않는다. 수동 복붙 루프로 폴백한다.
- Seedance 영상 평가를 안정적인 전용 MCP가 있는 것처럼 가정하지 않는다. 기본은 수동 실행과 결과물 첨부다.
- 최대 3회 반복 한도를 넘겨 무한 재생성하지 않는다.
