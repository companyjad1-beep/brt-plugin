# 체크리스트 자가채점 절차

이 절차는 프롬프트 파일을 정식 평가 전에 작성자가 직접 점검하는 `layer=checklist` 평가이다. 목적은 자기보고식 통과 선언이 아니라, 체크리스트 항목별로 추적 가능한 근거를 남기고 미달 항목만 다시 개선 루프로 돌려보내는 것이다.

## 1. 대상 체크리스트 선택

1. 평가 대상 프롬프트 파일의 생성 대상이 이미지이면 `core/checklists/image.checklist.yaml`을 사용한다.
2. 평가 대상 프롬프트 파일의 생성 대상이 영상이면 `core/checklists/video.checklist.yaml`을 사용한다.
3. 체크리스트 선택은 파일명 추정이 아니라 체크리스트의 `target` 필드(`image` 또는 `video`)와 프롬프트 대상의 일치 여부로 결정한다.
4. 대상이 불명확하면 평가를 통과 처리하지 않는다. 먼저 프롬프트의 대상 생성 타입을 확정한 뒤 다시 채점한다.

## 2. 채점 범위

체크리스트의 `scoringScope`를 그대로 따른다. `finalText`만 단독으로 채점하지 않고, 프롬프트 파일 전체를 기준으로 평가한다.

포함 범위:

- `finalText`
- `designMemo`
- `variants`
- `referenceImagePaths`
- `characterSheetRef`
- 그 밖에 프롬프트 파일 안에서 생성 결과에 영향을 주는 필드

즉, 최종 문장에는 짧게 쓰였지만 `characterSheetRef`나 참조 이미지 역할 선언으로 보강된 정보가 있으면 그 근거까지 함께 본다. 반대로 메모에만 의도가 있고 실제 프롬프트·참조 규약으로 연결되지 않으면 충족 근거로 과대평가하지 않는다.

## 3. 항목별 판정 형식

각 적용 항목은 아래 네 가지 중 하나로 판정하고, 반드시 근거 문장을 함께 적는다.

- `충족`: 항목 요구가 프롬프트 파일 전체에서 행동 가능한 형태로 충분히 확인된다.
- `부분 충족`: 관련 단서는 있으나 구체성, 위치, 역할, 제약 중 일부가 부족하다.
- `미달`: 항목 요구가 없거나 제너릭 표현에 가까워 생성 결과를 제어하기 어렵다.
- `판정 불가`: 적용 여부나 근거를 현재 파일만으로 판단할 수 없다. 단, `해당 시` 항목이 실제로 해당하지 않는 경우에는 `판정 불가`가 아니라 제외한다.

근거 문장은 체크리스트 질문에 직접 답해야 한다. “전체적으로 잘 작성됨”, “품질이 높음”, “문제가 없어 보임” 같은 총평은 항목 근거가 아니다.

## 4. `해당 시` 항목 제외 규칙

체크리스트 질문에 “해당 시 필수다”, “있는 경우”, “필요한 경우”, “등장하는 경우”, “요청인 경우”가 포함된 항목은 조건부 항목이다.

- 조건이 실제 프롬프트에 해당하면 적용 항목으로 채점한다.
- 조건이 해당하지 않으면 결과 목록에서 제외하고 합격 계산의 분모에 넣지 않는다.
- 제외 항목은 `eval-report.items`에 넣지 않는다.
- 대신 평가 리포트를 보관하는 증거 본문에 `제외 기록` 섹션을 두고, 제외 항목 id와 제외 사유를 목록으로 남긴다. 이 섹션은 `eval-report` JSON의 필드가 아니며 스키마를 변경하지 않는다.
- 해당 여부가 불분명하면 제외하지 말고 `판정 불가`로 기록한다.

예: 이미지 안 텍스트가 없는 순수 제품 컷이면 이미지 내 텍스트 항목은 제외한다. 그러나 광고 배너처럼 카피 여백이나 헤드라인이 필요한지 불분명하면 제외하지 않고 근거와 함께 `판정 불가`로 둔다.

## 5. 합격 기준

합격은 적용 항목 전부가 `충족`일 때만 가능하다.

- 적용 항목 중 하나라도 `부분 충족`, `미달`, `판정 불가`이면 전체 `verdict`는 `failed`다.
- `부분 충족`은 합격으로 보지 않는다.
- 조건부 제외 항목은 합격 계산에서 제외한다.
- 적용 항목이 0개가 되는 평가는 유효하지 않으며 통과 처리하지 않는다.

## 6. 불합격 시 루프 복귀

불합격이면 프롬프트 작성 루프로 돌아가되, 미달 원인에 해당하는 항목만 개선한다.

1. `부분 충족`, `미달`, `판정 불가` 항목을 식별한다.
2. 해당 항목의 질문과 근거 문장을 기준으로 프롬프트 파일을 수정한다.
3. 이미 `충족`인 항목은 불필요하게 재작성하지 않는다.
4. 수정 후 동일한 체크리스트와 동일한 `scoringScope`로 다시 자가채점한다.

이 규칙은 개선 과정에서 통과 항목을 흔들어 회귀시키는 것을 막기 위한 것이다.

## 7. 자기보고 금지

다음 방식은 금지한다.

- 항목별 근거 없이 전체 항목을 일괄 `충족`으로 표시한다.
- 체크리스트 질문을 읽지 않고 “작성자가 의도했으므로 충족”이라고 쓴다.
- `finalText` 일부 표현만 보고 프롬프트 파일 전체 기준의 누락을 무시한다.
- 실패 항목을 고치지 않고 표현만 긍정적으로 바꿔 재채점한다.

자가채점은 신뢰 가능한 평가 기록이어야 하며, 자기 확신이나 작성 의도는 근거를 대체하지 못한다.

## 8. 평가 리포트 저장 예시

결과 파일은 `workspace/reports/` 아래에 `eval-report` 스키마로 저장한다. 예: `workspace/reports/2026-07-07-wellness-launch-checklist.json`

```json
{
  "schemaKind": "eval-report",
  "schemaVersion": 1,
  "id": "eval-2026-07-07-wellness-launch-checklist",
  "promptRef": "workspace/prompts/2026-07-07-wellness-launch.yaml",
  "layer": "checklist",
  "verdict": "failed",
  "items": [
    {
      "item": "image-subject-specificity",
      "verdict": "충족",
      "evidence": "프롬프트 파일이 주 피사체를 30대 여성 러너, 민트색 윈드브레이커, 흰색 러닝화, 손목 스마트밴드로 고정해 외형 단서를 제공한다."
    },
    {
      "item": "image-composition-camera",
      "verdict": "부분 충족",
      "evidence": "정사각형 광고 컷과 제품 전면 배치는 지정되어 있으나 카메라 앵글과 여백 위치가 충분히 분리되어 있지 않다."
    },
    {
      "item": "image-hard-constraints",
      "verdict": "미달",
      "evidence": "랜덤 로고와 워터마크 금지는 있으나 추가 인물, 추가 제품, 과도한 장식 금지가 행동 가능한 문장으로 닫혀 있지 않다."
    }
  ],
  "createdAt": "2026-07-07T09:00:00+09:00"
}
```

위 예시는 적용 항목 중 `부분 충족`과 `미달`이 있으므로 전체 `verdict`가 `failed`다. 조건부 항목 중 실제로 해당하지 않는 항목은 `items`에 넣지 않고, 같은 증거 본문에 아래처럼 `제외 기록` 섹션으로 남긴다.

```markdown
## 제외 기록

- `image-in-frame-text`: 이미지 안 텍스트가 없는 순수 제품 컷이므로 적용 조건에 해당하지 않는다.
```
